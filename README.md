# SchemaLake

原创的类型化数据湖摄取与快照引擎，Python 3.11+标准库实现。输入是设备读数、采集批次和维度数据，输出是不可变分区数据对象、可追溯快照、清洗/聚合派生表及下游结构化消费结果。没有网页采集、购物/订单/库存后台、Excel导入、报表或看板；命令行和HTTP仅是数据引擎的操作入口。

本项目由本次对话原创实现，未声称来自上游开源仓库。较早的6文件草稿是同一项目的开发草稿，不作为另一个项目计数。

## 运行

所有项目数据生成、测试和演示在用户指定ECS的Linux Docker中进行；不需要模型API或安装Python依赖。

```bash
python3 -m unittest discover -s tests -v
python3 -m schemalake --home /tmp/lake serve --host 127.0.0.1 --port 8762
```

`Lake(home)`是领域服务入口。catalog.sqlite保存事务元数据；objects中是按内容寻址的数据文件和完整快照清单；exports是不可变输出副本。独立Mirror使用另一份SQLite消费库。HTTP默认仅监听环回地址，用于可信隔离环境。

## 已实现的数据语义

- 表Schema含稳定正整数field id、类型、空值、默认值、主键和分区列；当前版本只支持创建时Schema，不提供演进接口。decimal以十进制字符串精确表达、规范化等值形式；timestamp统一到UTC；布尔值不冒充int64。
- 批次追加最多100000行，批次ID相同且原始输入/策略相同则重放；同ID不同输入拒绝。主键在当前表内唯一。reject策略整批回滚，quarantine策略隔离行级问题；收据、键、拒绝记录、清单指针和head同事务生效。
- 文件写入先于catalog提交，失败可以留下不可见的孤立对象；不能把孤立对象当成已提交数据。原始对象和已发布清单不改写。当前保留全部历史，不自动清理文件或快照。
- 支持按分区替换、整表替换及小文件合并；旧快照继续读取当时结果。基线compaction持有写事务完成对象读写，对大分区会阻塞其他写入。
- 扫描可按分区相等条件剪枝。行级Predicate支持三值逻辑、AND/OR/NOT、比较、IN与IS NULL。过滤查询先用文件级min/max/null_count统计做三值逻辑安全的文件剪枝（decimal按精确数值比较、全空列与证据不足的文件保守保留、组合条件不丢可能结果），再对通过的文件逐行过滤，结果与纯逐行过滤完全一致。
- 主键点查及范围查可用固定快照的索引。索引构建读取结束后对head做CAS校验；索引与请求快照不匹配时扫描对应固定快照。历史查询不能误用最新索引。
- Typed JSONL/CSV导入导出（导出可带过滤表达式，与扫描查询共用同一统计剪枝和逐行过滤链路）、gzip与普通JSONL混合对象读取、流式分块JSONL导入、数据湖快照交换包、稳定外排序、逐行快照差异及消费端核对均可实际运行。流式输入要求文件冻结，失败后同文件/分块策略可重试；追加已成功的分块可见，不承诺整个大文件原子生效。
- StagedIngestor先登记preparing，再写对象并转prepared，最后CAS提交。准备中断的preparing记录可明确abort；不支持自动接管仍在工作的准备者。已提交批次不能abort。
- 清洗表达式、分组聚合和维度关联可生成目标湖表；基线刷新读取指定源快照并整表替换结果，没有增量刷新水位。派生运行记录保留源/目标快照依据。
- RoutedIngestor将同一输入拆成多个表批次，基线逐目标提交，各目标各有收据；后一个失败时先前目标仍可见。这个行为是当前契约，不声称已支持跨表原子发布。
- 清单格式v1在每个快照中写入完整文件描述数组。尚无CDC更新/删除语义、Schema演进、快照清理或v2清单迁移。

## 示例Schema

```json
{"fields":[{"id":1,"name":"id","type":"int64"},{"id":2,"name":"day","type":"date"},{"id":3,"name":"site","type":"string"},{"id":4,"name":"reading","type":"decimal","nullable":true}],"primary_key":["id"],"partition_by":["day"]}
```

示例记录：`{"id":1,"day":"2026-11-01","site":"station_a","reading":"12.50"}`。CSV使用`\N`表示空值，原本以反斜杠开头的字符串加一层反斜杠转义，布尔文本用true/false。

## 边界

本引擎提供数据处理与持久化功能，不是通用文件管理、目录同步或格式转换小工具。API不提供身份管理及公网部署能力。源码、测试和使用文档属于基线；题面、设计卡、隐藏探针、模型凭据和作者台账必须留在基线之外。
